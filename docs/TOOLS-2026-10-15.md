# Local code-search benchmark tool research

Checked 2026-10-15, approximately 23:06 UTC, using public upstream GitHub REST APIs through `gh api`, release notes, tagged documentation and tagged source. This research used public sources only. The accompanying benchmark report records which tools were subsequently installed and tested. No global tools or agent settings were changed.

## Recommended additions

Test **ugrep** for literal/regex searches and **ast-grep** for structural searches. They add different capabilities. Keep structural task results separate from exact text matching.

| Addition | Stable version | Why test it | macOS arm64 |
|---|---|---|---|
| ugrep | [7.8.5][ug-release], 2026-09-15 | Actively maintained parallel grep; fixed strings, regex, JSON output, optional fuzzy matching and compressed-file search. Good direct comparison with ripgrep on a shared file corpus. | Native source build; Homebrew arm64 bottles. |
| ast-grep | [0.51.0][ast-release], 2026-10-15 | Tree-sitter AST patterns can find calls or declarations despite whitespace and syntax variation. Useful alongside graph tools for structural tasks; it does not supply a repository call graph. | Official Apple Silicon ZIP. |
| Silver Searcher, optional | [2.2.0 source tag][ag-tag], 2018-08-07 | Familiar historical literal/regex baseline, but upstream's latest default-branch commit is from 2020. Less useful than the first two for a fresh tool comparison. | Homebrew arm64 bottles; its build includes an unofficial PCRE2 patch. |

Sources for capabilities and packaging: [ugrep README][ug-doc], [ast-grep README][ast-doc], [Silver Searcher README][ag-doc], [Homebrew ugrep formula][ug-brew], [Homebrew Silver Searcher formula][ag-brew].

## Compatibility and offline behavior

- **ripgrep 15.2.0:** changes include directory-traversal improvements and gitignore fixes. It now respects `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM`. Pin ignore inputs; use `--no-config` to exclude a user's ripgrep config. It is a local CLI with no online search dependency; the checked docs describe no telemetry option. [Release][rg-release], [guide](https://github.com/BurntSushi/ripgrep/blob/15.2.0/GUIDE.md)
- **fff 0.11.0:** SDK `FileFinder.create(...)` returns a `Result`; wait for `waitForScan`, handle `ok/value/error`, and call `destroy()`. Node/Bun options still expose `smartCase`, not `case_mode` or `casing`. Use `smartCase:false` for case-sensitive literal comparisons. Released Rust uses `casing:Option<Casing>` and retains `smart_case`. The release/PR title's `case_mode` spelling is misleading for the final API. Defaults include a 10 MB file limit, 200 matching lines per file and 50 results per page. Drain `nextCursor`, normalize caps, and use `timeBudgetMs:0` for complete-result timing. `enforceTimeBudget` now covers zero-match searches. [SDK definitions][fff-api], [Rust options][fff-rust], [release][fff-release]
- **fff offline/state:** MCP performs a GitHub release check by default. Pass **`--no-update-check`**. For static fixtures also pass `--no-watch`, route `--log-file` into the benchmark directory, and omit `--frecency-db`/`--history-db` unless measuring those features. SDK equivalents include `disableWatch:true`; omit its database/log paths for fresh state. Warmup/content-index settings affect results and must be recorded. No separate telemetry opt-out was found in the checked fff docs; the release check is a confirmed network call. [MCP arguments and startup][fff-main], [update-check implementation][fff-updates], [SDK definitions][fff-api]
- **codebase-memory 0.11:** upgrading from older formats rebuilds once; File qualified names now keep extensions. CLI/MCP output defaults to compact text, with pagination and reversible byte-string escaping. Use tool `--format json` for machine parsing; outer `--json` returns the full MCP envelope. Inline JSON arguments are deprecated in favor of flags, stdin or `--args-file`. The project explicitly states local operation and **no telemetry**. [0.11 release][cbm11-release], [CLI/privacy docs][cbm11-doc]
- **codebase-memory 0.12:** rebuild pre-0.12 indexes and re-run cross-repo linking. Qualified names and some edge meanings changed, including `SPAWNS` for program launches. Documentation indexing adds work; `doc_candidates` runs by default in full mode, but not moderate/fast, so record mode/settings. `search_code` uses case-sensitive extended regex and skips binary files; graph-ranked results and indexed-file scope differ from unrestricted grep. [0.12 release][cbm-release]
- **Graphify 0.9.91:** AST cache schema changed, causing a first-build re-extraction. For a fresh offline code benchmark use `graphify extract <public-fixture> --code-only --out <benchmark-output>`. Docs/media extraction can select a remote LLM automatically from environment keys; `--code-only` skips that pass. The project explicitly states **no telemetry**. Set `GRAPHIFY_QUERY_LOG_DISABLE=1` to avoid its default user-cache query log. Its dependency manifest requires tree-sitter `>=0.25,<0.26`; older runtime ABIs cannot load some included grammars. [Release][graph-release], [privacy docs][graph-doc], [manifest][graph-manifest]
- **ugrep:** 7.8.5 changes matching-mode flag precedence and encoding/decompression behavior. Use `ugrep`, since `ug` automatically loads user/project `.ugrep` config. Ignore rules require explicit settings, such as `--ignore-files --no-hidden -I`; preferably compare a common enumerated corpus. It is a local CLI with no online search service or documented telemetry setting. [Release][ug-release], [README][ug-doc]
- **ast-grep / Silver Searcher / BSD grep:** local CLI search needs no remote backend, and the checked upstream docs describe no telemetry switch. Use ast-grep's search commands without rewrite flags. AST language/grammar semantics and grep regex semantics differ; a shared pattern string does not establish an equivalent task. [ast-grep docs][ast-doc], [ag manual](https://github.com/ggreer/the_silver_searcher/blob/2.2.0/doc/ag.1.md), [Apple grep manual][apple-man]

## codebase-memory 0.11 daemon isolation

**Set both `CBM_RUNTIME_DIR` and `CBM_CACHE_DIR`.** A cache override alone does not move the rendezvous. By default macOS uses `/private/tmp/cbm-daemon-<uid>`; its admission barrier checks exact version/build/ABI and canonical cache root. A conflicting cache is rejected even for a one-shot CLI command. CLI commands do not start/connect to the daemon, but still acquire admission leases. Native install/update/uninstall intentionally cancel active coordinated work, so they are unsuitable here. [Configuration][cbm11-config], [coordination and CLI docs][cbm11-doc]

The production `CBM_RUNTIME_DIR` override goes through the shared endpoint constructor for daemon, MCP, CLI, worker and activation. The version-cohort locks use that endpoint's private lock directory. Thus a fresh runtime parent isolates the socket **and** admission state. This is supported in the shipped 0.11 source; it does not require `CBM_TEST_DAEMON_RUNTIME_PARENT` or a test build. The override remains in 0.12. [0.11 bootstrap][cbm11-bootstrap], [0.11 endpoint layout][cbm11-ipc], [cohort lock placement][cbm11-cohort], [0.12 bootstrap][cbm12-bootstrap]

Proposed wrapper, to be used later with an unpacked release binary and a public fixture:

```sh
cbm_bench_root="$(mktemp -d /private/tmp/cbmb.XXXXXXXX)"
mkdir -m 700 "$cbm_bench_root/r" "$cbm_bench_root/c" "$cbm_bench_root/x"
cbm_bench_binary="/absolute/path/to/unpacked/codebase-memory-mcp"
cbm_bench_fixture="/absolute/path/to/public-fixture"

cbm_bench() {
  env CBM_RUNTIME_DIR="$cbm_bench_root/r" \
      CBM_CACHE_DIR="$cbm_bench_root/c" \
      XDG_CONFIG_HOME="$cbm_bench_root/x" \
      CBM_ALLOWED_ROOT="$cbm_bench_fixture" \
      "$cbm_bench_binary" "$@"
}

cbm_bench config set auto_index false
cbm_bench config set auto_watch false
cbm_bench config set watcher_enabled false
cbm_bench cli index_repository --repo-path "$cbm_bench_fixture"
cbm_bench cli list_projects --format json
```

For warm MCP measurements, launch `cbm_bench --ui=false` under a dedicated stdio client with the same environment and a working directory inside the fixture. Keep stdin open and use that client, rather than the already-connected workspace MCP server. If the benchmark started a daemon, close its MCP session and use only the wrapper for `daemon status` or `daemon stop`. Never run an unwrapped stop command. Use a separate fresh root for each CBM version.

Runtime ancestry must pass ownership/mode/ACL checks: ancestors owned by the user/root, no unsafe write permissions or allow-ACLs, with the standard root-owned sticky temp-directory exception. Keep the path short for Unix socket limits. This research phase checked public docs/source only. The subsequent benchmark validated isolated 0.12.0 operation; see the October report for the actual environment and controls. [Configuration][cbm11-config]

## Benchmark implications

Measure process startup/cold indexing, warm query time, peak/RSS memory and complete-result correctness separately. Record the binary SHA-256, native architecture, OS build, library/runtime versions and options. For fff distinguish scan completion from content-index/warmup readiness. For graph tools verify index readiness and coverage before timing queries.

Use separate task sets for literal lines, regex matches, fuzzy file discovery, AST patterns and graph relationship queries. Normalize case, file corpus, hidden/binary/symlink treatment, result limits and pagination. FFF's definition classifier is a byte-level heuristic, while ast-grep matches AST structure and graph tools resolve relationships. Their result counts are not interchangeable. [FFF architecture][fff-doc], [ast-grep introduction][ast-doc], [Graphify architecture](https://github.com/Graphify-Labs/graphify/blob/v0.9.91/docs/how-it-works.md)
